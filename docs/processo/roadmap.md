## Plano de finalização — reuniões de 24/09 e 10/10/2026

**O prazo passou a mandar no escopo.** Na reunião de 10/10/2026 o orientador fixou: a
implementação termina em **12/10/2026**, e a partir daí o aplicativo não recebe mais
alteração. O tempo restante vai para testes com usuários e para o artigo.

Duas dependências estruturam o que resta. A primeira é a de sempre: **o aplicativo precisa
congelar antes de a coleta começar** — corrigir um problema no meio faria os participantes
avaliarem sistemas diferentes, e a consolidação por heurística deixaria de somar. A
segunda é nova: **a seção de Resultados do artigo não pode ser escrita antes de os dados
existirem**, e por isso ela é a última a ser redigida.

## Como rodar os testes

```
python -m pytest              # camada rápida (~45 s): motor, conformidade do CCAE, telas, laudo
python -m pytest --completa   # tudo, inclusive as bancadas lentas (~4 min 30 s)
```

Rode a completa antes de todo push e sempre que mexer na base de conhecimento, no formulário ou
no despacho de grupos. A conformidade do CCAE fica na camada rápida de propósito: é o oráculo do
trabalho, e uma alteração que a quebre precisa aparecer na hora.
